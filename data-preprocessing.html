Preparing healthcare data for machine learning with Scikit-learn.

1. What is Data Preprocessing?

Data preprocessing is the critical first step in any machine learning pipeline. It involves cleaning, transforming, and formatting raw data into a clean, consistent, and usable dataset. Real-world healthcare data is almost always "dirty"—it can be incomplete, inconsistent, contain typos (e.g., 'Diabetic', 'Dibetec'), impossible values (e.g., `Age: 500`), or different units (e.g., `kg` vs. `lbs`).

Why It's Non-Negotiable in Healthcare

Garbage In, Garbage Out (GIGO)

Models are only as good as their data. Biased, messy, or incomplete data will lead to dangerously inaccurate predictions. In healthcare, this can lead to misdiagnosis, incorrect risk stratification, or biased resource allocation.

Models Speak Math, Not Text

Algorithms can't understand 'Female', 'Type A', or 'High Risk'. They require numbers. Preprocessing translates this qualitative information into a quantitative format the model can understand.

Performance and Accuracy

Features on different scales (e.g., 'Age' 20-80 vs. 'Lab Value' 0.1-1.5) can bias a model. Scaling ensures all features are weighted fairly, leading to a more accurate and reliable model. The right method depends on the model and data.

2. Handling Missing Data (Imputation)

Healthcare data is notoriously messy. Lab tests may not be ordered (MAR), sensor readings can be lost (MCAR), or a patient may be too ill to answer a survey (MNAR). Models cannot handle these "NaN" (Not a Number) values, so we must fill them in, or "impute" them.

Naive Strategy: Dropping Data

The simplest option is to drop rows (`.dropna(axis=0)`) or columns (`.dropna(axis=1)`) with missing values. This is rarely a good idea, as you lose valuable patient information and can even introduce bias if the missingness isn't random.

Simple Imputation (Mean/Median/Mode)

We fill missing values with a statistic from that column. Use `strategy='median'` for numeric data with outliers, `mean` for normally distributed data, and `most_frequent` for categorical data.

from sklearn.impute import SimpleImputer
import numpy as np

X = [[120, np.nan], [124, 72.0], [np.nan, 80.0], [130, 75.0]]
# Use median (robust to outliers)
imputer = SimpleImputer(strategy='median')
X_imputed = imputer.fit_transform(X)

Advanced Imputation (KNN)

`KNNImputer` finds the 'K' most similar patients (neighbors) and uses their values to fill the missing spot. This is context-aware. Important: You must scale your data *before* using KNNImputer, as it's distance-based.

from sklearn.impute import KNNImputer
from sklearn.preprocessing import StandardScaler

X = [[1.0, 2.0, np.nan], [3.0, 4.0, 3.0], [4.0, 5.0, 4.0]]
scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)

imputer = KNNImputer(n_neighbors=2)
X_imputed_scaled = imputer.fit_transform(X_scaled)

Model-Based Imputation (Iterative)

`IterativeImputer` is the most powerful. It treats the missing feature as a target variable (y) and all other features as (X), then trains a regression model (like Random Forest) to predict the missing value. It's powerful but computationally slower.

# Enable it: from sklearn.experimental import enable_iterative_imputer
from sklearn.impute import IterativeImputer
from sklearn.ensemble import RandomForestRegressor

imputer = IterativeImputer(
    estimator=RandomForestRegressor(),
    initial_strategy='median',
    max_iter=10, 
    random_state=0
)
X_imputed = imputer.fit_transform(X)

3. Encoding Categorical Data

Models understand numbers, not text. We must convert categorical features like "Blood Type" or "Triage Priority" into a numeric format.

Ordinal Encoding (For Order)

Used for categorical data that has an *inherent order* (e.g., `low < medium < high`). We map each category to a single integer that respects this order. This is the correct choice for ordinal features.

from sklearn.preprocessing import OrdinalEncoder

data = [['low'], ['high'], ['medium'], ['low']]
# Define the explicit order
categories = [['low', 'medium', 'high']]

encoder = OrdinalEncoder(categories=categories)
data_encoded = encoder.fit_transform(data)
# Result: [[0.], [2.], [1.], [0.]]

One-Hot Encoding (No Order)

Used for *nominal* data (no order), like "Blood Type". It creates a new binary (0 or 1) column for each category. Use `drop='first'` to avoid multicollinearity in linear models.

from sklearn.preprocessing import OneHotEncoder

data = [['A'], ['B'], ['AB'], ['O']]

encoder = OneHotEncoder(sparse_output=False, drop='first')
data_encoded = encoder.fit_transform(data)
# Result (3 cols): [[0,0,0], [1,0,0], [0,1,0], [0,0,1]]
# Categories: A(dropped), B, AB, O

Warning: LabelEncoder vs. OneHotEncoder

A common mistake is to use `LabelEncoder` on *features* (X). `LabelEncoder` turns `['A', 'B', 'O']` into `[0, 1, 2]`. This incorrectly tells the model that `O > B > A`, which is meaningless. `LabelEncoder` should only be used to encode the target variable (y). Use `OneHotEncoder` for all nominal features.

4. Feature Scaling

Many models are sensitive to the scale of features. If 'Age' (20-80) is 100x larger than 'Lab Value' (0.1-1.5), the model will mistakenly think 'Age' is 100x more important. Scaling fixes this.

Before Scaling (Data is Skewed)

Notice how the 'Age' (X-axis) is very spread out, while the 'Lab Value' (Y-axis) is compressed. An algorithm using Euclidean distance would be completely dominated by Age.

After StandardScaler (Data is Centered)

`StandardScaler` transforms each feature to have a mean of 0 and standard deviation of 1. Now, both features are on the same scale, and the model can learn their true relationship.

Which Scaler to Use?

  • StandardScaler: The default choice. Good for data that is roughly normally distributed.
  • MinMaxScaler: Scales to a [0, 1] range. Often preferred for neural networks. Sensitive to outliers.
  • RobustScaler: Uses median and interquartile range (IQR). This makes it robust to outliers. Use this if your data has many extreme, potentially erroneous, values.

Which Models Need Scaling?

  • YES (Scaling is critical): Linear/Logistic Regression (with regularization), K-Nearest Neighbors (KNN), Support Vector Machines (SVMs), Neural Networks, Principal Component Analysis (PCA).
  • NO (Scaling doesn't matter): Decision Trees, Random Forests, Gradient Boosting (XGBoost, LightGBM). These models are tree-based and split on feature values, regardless of their scale.

5. Feature Engineering

This is the art of creating new, more informative features from the data you already have. A good feature can be the difference between a poor model and a great one. This often requires domain expertise—talking to doctors and nurses about what's clinically relevant.

Example: Date/Time Features (Pandas)

An admission timestamp isn't just a time. It's a day of the week, an hour of the day, or a month. Risk of complications might be higher on a weekend or during a night shift. We can extract these with `pandas`.

import pandas as pd
df = pd.DataFrame({'admission_time': ['2023-01-01 02:00', '2023-01-03 14:00']})
df['admission_time'] = pd.to_datetime(df['admission_time'])

# Create new features
df['admission_hour'] = df['admission_time'].dt.hour
df['admission_dayofweek'] = df['admission_time'].dt.dayofweek
# [2, 14] and [6 (Sunday), 1 (Tuesday)]

Example: Polynomial Features

If a linear model can't capture a non-linear trend (e.g., risk is low, then high, then low again as a lab value changes), we can add squared (`x²`) or cubed (`x³`) terms. `PolynomialFeatures` helps create these and interaction terms (`a*b`).

from sklearn.preprocessing import PolynomialFeatures

X = [[2, 3]] # [Age, BP]
poly = PolynomialFeatures(degree=2, include_bias=False)
X_poly = poly.fit_transform(X)
# Result: [[2, 3, 4, 6, 9]]
#           [a, b, a^2, a*b, b^2]

6. Handling Imbalanced Data

A critical problem in healthcare. If you're predicting a rare disease (1% of patients), a model that just guesses "no disease" every time is 99% accurate but clinically useless. We must rebalance the dataset or adjust the model.

Before Resampling (Imbalanced)

The model will be heavily biased towards the "Negative" class and will likely ignore the few "Positive (Disease)" cases.

After SMOTE (Oversampled)

SMOTE synthetically creates new "Positive" samples. Now the classes are 50/50, forcing the model to learn the patterns that identify the rare disease.

Method 1: Resampling (SMOTE)

SMOTE (Oversampling) is popular. You can also do `RandomUnderSampler` (deletes majority samples), but this risks losing data. Crucially: Only resample the *training* set.

# Requires: pip install imbalanced-learn
from imblearn.over_sampling import SMOTE
from sklearn.model_selection import train_test_split

# Split data FIRST
# X_train, X_test, y_train, y_test = train_test_split(X, y)

smote = SMOTE(random_state=42)
# ONLY resample the training data
# X_train_res, y_train_res = smote.fit_resample(X_train, y_train)

# Train on resampled, test on original test set
# model.fit(X_train_res, y_train_res)
# model.score(X_test, y_test)

Method 2: Adjust Model & Metrics

Instead of changing the data, change the model. Many classifiers (like `RandomForest`) have a `class_weight='balanced'` parameter. This tells the model to penalize mistakes on the minority class more heavily.

Also, stop using 'Accuracy'. Use metrics that are better for imbalanced data, like Precision, Recall, F1-Score, or the Precision-Recall Curve (AUPRC).

from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import f1_score

# Let the model handle the imbalance
model = RandomForestClassifier(class_weight='balanced', random_state=42)
